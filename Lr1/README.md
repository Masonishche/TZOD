# Лабораторна робота 1: Обробка пропусків та аналіз даних електронної комерції

### Виконав: Студент групи ТВ-33 Чернявський Максим

## Мета роботи
Навчитися виявляти пропуски в даних, застосовувати методи групової імпутації (заповнення пропусків) та оцінювати вплив обробки даних на ключові бізнес-метрики (наприклад, середній чек).

## Набір даних (Dataset)
У роботі використано **E-commerce Sales Transactions Dataset** з платформи Kaggle. Датасет містить понад 34 500 записів реалістичних транзакцій, включаючи ідентифікатори товарів (`product_id`), ціни (`price`), кількість (`quantity`) та знижки (`discount`).

## Хід роботи

1. **Завантаження та підготовка даних:** Дані були автоматично завантажені за допомогою бібліотеки `kagglehub`. Оскільки вихідний датасет був чистим, для імітації реальних "брудних" даних було штучно згенеровано пропуски (15% у колонці `quantity` та 10% у колонці `discount`).

2. **Розвідувальний аналіз (EDA):** Побудовано звіт про кількість та відсоток пропусків по кожній колонці для розуміння масштабу проблеми.

3. **Розрахунок базової метрики:** Обчислено середній чек до обробки даних (виключно на "чистих" рядках, що не містили NaN) за формулою: `price * quantity * (1 - discount)`.

4. **Імпутація даних:** Замість заповнення пропусків нулями або глобальним середнім значенням, було застосовано більш точний метод: **заповнення медіаною по групах**. Пропуски в `quantity` та `discount` заповнювалися медіанним значенням для кожного конкретного товару (`product_id`).

5. **Оцінка результатів:** Повторний розрахунок середнього чеку на відновленому датасеті та порівняння результатів.

## Отримані результати

### Звіт пропусків (до імпутації)
* **discount**: 3450 пропусків (10.0%)
* **quantity**: 5175 пропусків (15.0%)

### Результати імпутації
Після заповнення медіаною по `product_id` кількість пропусків значно зменшилася:
* Залишилось пропусків у `quantity`: **2876**
* Залишилось пропусків у `discount`: **1864**

* Інсайт:* Наявність залишкових пропусків є нормальною для реальних даних. Це означає, що для певних `product_id` **усі** доступні записи були пустими (NaN), відповідно алгоритм фізично не зміг вирахувати для них медіану.

### Порівняння бізнес-метрик
* Середній чек ДО імпутації: **$172.08**
* Середній чек ПІСЛЯ імпутації: **$171.35**

##  Висновок
Групова імпутація медіаною дозволила врятувати значну частину транзакцій для подальшого аналізу. Відновлення даних майже не вплинуло на фінансові показники (різниця середнього чеку склала всього ~$0.73), що підтверджує високу точність та безпечність обраного методу обробки пропусків.
